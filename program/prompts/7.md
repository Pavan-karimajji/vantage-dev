## Goal
`modules/vantage/docs/VANTAGE_Lab_Design.md` exists. Read alone, it says how a lab
component is described, generated and built with the standard toolchain; how the
fake car produces recordings with the known right answer; which topologies the
catalogue holds and how each `F-…` fixture is made; the file and symbol of every
`IMP-0022`..`IMP-0031` job; and the lab's own build order, so `WP-06` and `WP-07` can
be built from it.

## Stated inputs (decided; build on them)
1. **Small on purpose** (plan §4): one C++ component template, one Python script that
   fills it from a YAML description file. No code-generation framework, no plug-in
   system. Lab components are generated build outputs, not repos (D4).
2. **The algorithm is plain integer arithmetic** over the inputs read (plus a running
   sum for a component with memory), so a wrong input sample always changes the
   output. Deterministic: no clock, no random value, no unordered iteration (`IMP-0027`).
3. **Owner (R-NAME-3):** the template's knobs `max_age_us` and `recovery_runs`
   (`IMP-0024`, `IMP-0025`) are calibration keys: ALL_CAPS with a domain prefix and a
   unit suffix (for example `LAB_<COMP>_MAX_AGE_US`), read from the component's config
   bundle.
4. **The fake car's timing logic follows an existing executable model** (Python,
   about 150 lines; you do not have it — this is its behaviour, in full):
   - every component runs on its own task clock: a period, a phase, and a start
     jitter drawn from a seeded random generator;
   - at its start time it reads, for each input, the newest sample that exists at
     that moment; for a previous-cycle input, its own previous output;
   - the task cycle's id is the measurement counter stamped on everything the run
     makes; it writes its outputs and a record of the counters it read (the refSync);
   - sources produce samples on their own clocks;
   - the model's checks: with refSyncs, a resim equals the recording exactly for any
     cut and any order of independent components; without, mismatches are counted.
   The fake car is this model made real: it runs the **generated lab component
   libraries** through the generic ABI and records every port.
5. **The running example** (the model's first case): sources `X` period 10 ms, `Y` 25 ms
   (jitter 3 ms), `Z` 50 ms (jitter 5 ms); components `A` 20 ms reads `X` (jitter 2);
   `B` 40 ms reads `A`, `X`, `Y`, `Z` (jitter 4); `C` 20 ms reads `X`; `D` 20 ms reads
   `C` (jitter 2); `E` 30 ms reads `Y` (jitter 3). In a resim `A`, `B`, `D`, `E` are
   simulated and `C` is measured. **First milestone: this example only.**
6. **The catalogue's next topologies** (one file each, added one corner case at a
   time): fan-out (A→B, A→C), diamond (A→B, A→C, B+C→D), rates that are not multiples
   (20/30/70 ms), feedback through a previous-cycle input, a measured stage in the
   middle (A simulated, M measured, B simulated), a consumer that starts late (start
   jitter larger than the gap to its producer: the readiness case), a component
   triggered by an input port instead of its own clock, and a loop with no
   previous-cycle edge (must be refused at load).
7. **`F-LAB-RESTART`** needs the fake car to restart one named component at one
   scripted run (that run's recorded control carries RESTART). `IMP-0030` says
   "RESTART only on the first run"; propose the exact new Artifact text for
   `IMP-0030` in this document (a design-row edit the orchestrator lands separately).
8. **Provisional values** for the `⊘` run-setup values of 6a §4
   (`readiness_limit_steps`, `fallback_max_gap`, `buffer_depth`, the `MeasCycle` and
   `MeasBulk` geometry): give a provisional number for the lab's tests, each marked
   *provisional*, with how it is derived and how it will be measured. Never present
   one as final (R-REQ-10).
