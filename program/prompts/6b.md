## Fixed inputs (decided by the orchestrator so the script and the document agree)
- **Row UIDs are qualified** by set: `SIM:CN-0001`, `SIM:SYS-0001`, `SIM:SW-0001`,

  The universe is every **live** requirement row of the two sets; a UID that a sim v2
  document already lists as retired is not in the universe (say so in the register).
  Tests (`CT`, `SYT`, `UT`, …) are not dispositioned: they follow their requirement.
- **Row table format** (every row section): `| UID | Disposition | Target | Why |`.
- **Row disposition words** (closed list, one meaning each):
  - `carried` — the obligation stays in Vantage; a Plan C row (step 8) will hold it.
    Target: `VNT`, or a `VNT:` UID once step 8 allocates one.
  - `moved` — it now lives in the contract. Target: one or more `RCT:SYS-nnnn` /
    `RCT:IMP-nnnn`, comma-separated; each must exist.
  - `superseded` — a decision or the frozen architecture replaced it. Target: `D<n>`
    (must exist in the plan §2) or `ARCH §<n>` (must be a section of
    `VANTAGE_Architecture.md`).
  - `retired` — no longer needed. Target: `—`. `Why` must not be empty.
- **D15 inheritance:** an `IMP` row (either set) is not listed when every `SW` row it
  serves has the same disposition; it inherits it. It **must** be listed when its `SW`
  rows disagree. Listing an `IMP` whose `SW` rows agree on the same word is a finding
  (one fact in one place).
- **Code table format:** `| Path | Disposition | Target | Why |`, paths relative to
  `modules/vantage`. **Code disposition words** (closed): `reused` (kept as it is,
  inside a Vantage part — Target: the part, `ARCH §3.n`), `corrected` (kept and changed —
  Target: the part and what changes, citing `ARCH §n`), `replaced` (Target: the new
  file, per `ARCH §11`), `retired` (Target `—`, Why not empty). New Vantage files with
  no sim origin are **not** listed: `ARCH §11` already names them (cite it once).
  A row for a directory covers everything under it unless a deeper row overrides it.

## The script
`scripts/check_migration_register.py [--register <md>] [--selftest]`, file header per
the template (`COMPONENT: VANTAGE`), standard library only (plus PyYAML only if you
truly need `layers.yaml`; prefer reading the documents directly).
- Builds the universe from the two sets (formats above), qualified UIDs, retired
  rows excluded.
- Reads the register's row tables and code table.
- Findings (one line each, `C-<NAME> <uid or path>: <what>`): a universe UID neither
  listed nor inherited (`C-MISSING`), listed twice (`C-DUPLICATE`), a UID not in the
  universe (`C-UNKNOWN`), a word not in the list (`C-WORD`), a Target of the wrong
  form or pointing at nothing (`C-TARGET`), an empty Why where required (`C-WHY`), an
  `IMP` whose `SW` rows disagree and is not listed (`C-INHERIT`), an `IMP` listed
  though its `SW` rows agree on the same word (`C-REDUNDANT`), a code directory or
  file not covered or covered twice (`C-CODE`).
- Prints per section: universe count, listed, inherited, missing. Exit 0 only with no
  finding. Today the row sections are empty, so it exits 1 with every row UID missing:
  that is expected and is the starting point for 6c–6e.
- `--selftest`: builds a small in-memory universe and register, plants one violation
  per check, and fails if any planted violation is not caught (R-REQ-9).
- The test file runs `--selftest` and, for each check, a small case built in a temp
  directory, each check id in its test name.
