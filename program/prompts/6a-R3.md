## Owner decisions (2026-10-30, D18; do not reopen)
1. **Fallback by counter.** When a recorded refSync entry names a sample that is
   not found, the input falls back by counter: the newest sample whose
   `measurement_counter` is not after the wanted one, by `counterDistance`, badged
   `KIND_FALLBACK`. The time rule ("newest not after the trigger time") stays only
   for a stage with no recorded refSync.
2. **A component-under-test break is logged.** `KIND_IDENTITY_BROKEN` keeps exactly
   the D17 (3) meaning. A simulated output that does not copy its control's
   `measurement_counter` is a different fact (a `RCT:SYS-0001` break by the component
   under test): it goes to the engine's event log (stage, port, step) and the engine
   run goes on.
3. **The seal.** The live measurement is written only by the writer library; its
   seal call, used by the supervisor after the worker is confirmed dead, writes
   `outcome` and `status` and nothing else (`RCT_Architecture.md` §7).
4. **Run-setup keys.** `sampling` and `on_missing` are refused at load if present,
   never read and ignored.
5. **"Engine run".** "Run" keeps the contract meaning: one run of one component. The
   whole execution is an **engine run**: one outcome, one run id, one live
   measurement per engine run.

## Orchestrator design inputs (take as given)
- **Which samples the counter fallback may take.** It searches every sample in the
  input's buffer, read-ahead included: a sample whose counter is not after the
  wanted one was made before it, so the counter keeps the choice causal even if it
  was logged late. The time rule never looks into the read-ahead (the existing
  rejected option keeps that, narrowed to the time rule).
- **A maximum gap for the counter fallback is not decided yet.** Established
  practice accepts a fallback only within a fixed maximum counter gap; beyond it,
  it reports an error naming the port. Add it as **open question 13**: "Does the
  counter fallback need a maximum gap?" Recommendation: yes, one run-setup key
  `fallback_max_gap` (counter steps), value `⊘`. Beyond it the counter fallback
  takes nothing; the time rule picks the sample, `KIND_FALLBACK` is raised, and the
  event log records stage, port, wanted counter, found counter and gap. Do not add
  the key to §2.3 or §4 yet: the owner decides at the freeze.
