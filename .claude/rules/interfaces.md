# Rules — Interfaces / Contracts (R-IFACE)

Normative index. Detail: `docs/KT/architecture_overview.md` §3,
`docs/interfaces_types_migration.md`, `skills/protobuf_patterns.md`.

| ID | Rule |
|---|---|
| R-IFACE-1 | `modules/interfaces` is the **central contract repo** — the only place `.proto` schemas and shared C++ interface headers are defined; consumers link `AdasInterfaces::AdasInterfaces`. |
| R-IFACE-2 | **Folder = producer/organization, package = data domain** — independent axes. Producer folders (`PerceptionCore__Outputs/`, `Aeb__Outputs/`) are siblings under `proto/`; the `package` statement stays logically correct regardless of folder. |
| R-IFACE-3 | **Verified vs. legacy provenance:** only types checked for field-set completeness against real-world domain requirements get producer folders; naming is always project-native (snake_case, no Hungarian prefixes) regardless of verification status. Everything unverified carries a `PROVENANCE:` comment marking it so. Do not blur the line. |
| R-IFACE-4 | **A message that can be a port payload carries exactly one `sig_header` of type `adas.common.SignalHeader`; nothing nested inside it carries one.** Element types (`DfObj`, `Detection`), primitives, static calibration (`CameraIntrinsics`) and port *metadata* (`ComponentManifest`) do not. Filled by the producing component at its `ProPort` (R-ARCH-4) — never by the SIL shim, the recorder or a layer provider; an unfilled header is an explicit *unknown*, never back-filled from reception time (R-SIM-7, R-SIM-14). `sig_status` is the sender's "fit to use" sticker — `0` INIT (not ready, contents are defaults), `1` OK (use it), `2` INVALID (do not use it), constants in `adas/sig_status.hpp` — written only by the sender on its own messages; a receiver reads it and never rewrites it. The rule is about **shape**, not importance, so it needs no per-message judgement and is mechanically checkable. *Implemented 2026-10-20 (`docs/interfaces_signal_header_plan.md` §5 rows 1, 3, 4): `source_timestamp_us` (`uint64`, µs) and `optional capture_timestamp_us` are on the wire, every real producer fills its header at its `ProPort` (`df` from the cycle reference, `egoDyn`'s source time; `vdy` from its input), and `interfaces/scripts/check_signal_header.py` enforces the shape on every output payload. **Still open:** rows 5–7, the `modules/sim` recorder/bus reading the header by descriptor — until then a recording's cycle ladder lands on reception time. Spec history:* (2026-08-11), which also widens `time_stamp` to `uint64` because `uint32` nanoseconds wrap in 4.3 s, and splits it into two differently-named clocks — `source_timestamp_us` always filled, `capture_timestamp_us` proto3 `optional` and unset when unknown (`IFQ-06`). The **unit is microseconds**, ratified 2026-08-13 (`IFQ-01`), agreeing with `CN-0019`'s entry condition; a sub-microsecond source would truncate, so the bench sample's finest observed resolution is checked before any producer encodes. `cycle_counter` wraps at `uint32` and the bus handles wrap explicitly. Dummy messages with no producer are **not** retrofitted — the rule is scoped by "can be a port payload", so the check demands a header the day one gains a real producer.* |

See also: `rules/naming.md` (R-NAME-4), `workflows/add_proto.md`,
`rules/sim.md` (R-SIM-14 — the two clocks the header feeds; the recording owns
reception time, the payload owns source time).
